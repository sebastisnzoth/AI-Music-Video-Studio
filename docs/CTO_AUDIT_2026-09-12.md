# CTO Audit — AI Music Video Studio

Fecha: 2026-09-12

## Resumen ejecutivo

El repositorio **no es un prototipo vacío**. Ya posee una base importante de producción audiovisual local: análisis musical, storyboard, director visual, generación mediante ComfyUI/LocalAI, postproceso, review y assembly.

El principal riesgo actual no es falta de funciones creativas. Es **confiabilidad operativa del camino Vercel → render worker → proyecto persistente → MP4 final**.

## Hallazgos críticos

### 1. URL temporal del worker en `vercel.json`

Actualmente `RENDER_WORKER_URL` está apuntando a un dominio `trycloudflare.com` dentro del repositorio.

Riesgos:
- el túnel cambia o expira;
- un deploy puede quedar vinculado a una URL muerta;
- configuración operativa mezclada con código;
- difícil rotación/reemplazo del worker.

Acción P0:
- mover fuente de verdad a Environment Variables de Vercel;
- dejar la aplicación preparada para `worker missing/offline`;
- documentar procedimiento de conexión;
- luego eliminar el valor temporal hardcodeado cuando la variable esté confirmada en producción.

### 2. Contrato worker insuficientemente formalizado

La capa Vercel consulta health/checkpoints y actúa como controlador. Para producción debe existir una versión explícita del contrato entre ambos lados.

Acción P0:
- `/api/health`;
- `/api/capabilities`;
- jobs con IDs;
- status estructurado;
- error codes estables;
- request IDs;
- idempotencia.

### 3. Dependencia de estado local

El producto debe tolerar:
- refresh del navegador;
- redeploy de Vercel;
- caída/reinicio del worker;
- reinicio de ComfyUI.

Acción P0:
- manifiesto persistente de proyecto;
- estado persistente por escena/job;
- recuperación por IDs;
- evitar que la UI sea la fuente de verdad.

### 4. Ausencia de red de seguridad automatizada

No se detectó una suite de tests automatizados en la revisión inicial.

Acción P0:
- tests unitarios sin GPU;
- contract tests usando worker simulado;
- tests de state machine;
- smoke test deploy;
- E2E GPU marcado por separado.

### 5. Monolito UI/API en `app/vercel_app.py`

El archivo contiene FastAPI, lógica de conexión al worker, HTML, CSS y JavaScript inline.

No impide un MVP, pero aumenta riesgo de regresión y dificulta tests.

Acción P1, no bloquear P0:
- separar cliente worker;
- separar routes;
- extraer frontend estático/componentes cuando el flujo esté estable.

## Riesgos de seguridad a cerrar antes de uso público multiusuario

- límites de upload;
- MIME real y extensión;
- sanitización de filenames;
- prevención de path traversal;
- token compartido o auth control-plane ↔ worker;
- CORS limitado;
- rate limiting básico;
- no devolver paths internos/traces al navegador;
- no versionar secretos.

## Camino crítico recomendado

### Sprint P0-A — Worker confiable

1. formalizar `/api/health`;
2. agregar `/api/capabilities`;
3. worker URL solo por configuración de deploy;
4. diagnóstico visible;
5. probar checkpoint discovery;
6. probar un workflow de imagen conocido;
7. probar un workflow de video conocido.

**Exit:** Vercel puede descubrir, diagnosticar y mandar un job a un worker estable.

### Sprint P0-B — Estado persistente

1. project manifest;
2. scene manifest;
3. job manifest;
4. IDs estables;
5. reintentos idempotentes;
6. recuperación tras refresh/restart.

**Exit:** cerrar y volver a abrir no destruye el proyecto.

### Sprint P0-C — Happy path completo

1. upload;
2. analysis;
3. storyboard;
4. approve storyboard;
5. generate scene;
6. review/regenerate;
7. approve all;
8. assemble;
9. MP4 final.

**Exit:** fixture corta produce video final reproduciblemente.

### Sprint P0-D — Tests

1. worker fake;
2. API contracts;
3. state transitions;
4. worker unavailable;
5. duplicate/retry;
6. assembly validation;
7. smoke script.

**Exit:** cambios futuros no rompen silenciosamente el camino principal.

## Criterio de producto vendible

El MVP técnico se considera utilizable cuando un usuario puede:

```text
abrir la web
→ subir canción + referencia
→ crear storyboard
→ generar/revisar escenas
→ recuperar el proyecto si recarga
→ generar el master
→ obtener un MP4 válido
```

sin editar código, abrir terminal, reiniciar manualmente ComfyUI ni conocer rutas internas del servidor.
